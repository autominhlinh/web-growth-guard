# Community and maintainer roadmap

## Public preview scope

Web Growth Guard is an early MIT-licensed project. Its purpose is to help developers reproduce and prevent scoped SEO and growth regressions, not to guarantee indexing, search rank, AI mentions, traffic or revenue.

The release evidence is in the README. We welcome reports of installation problems, missing checks, false positives, and local MCP host compatibility. Keep issue reports synthetic and minimal. Use the private vulnerability reporting channel for security findings.

## Next maintenance priorities

- Reproduce reported defects; add a minimal regression test before fixing them.
- Verify additional operating systems and actual MCP hosts separately from SDK compatibility. Record exact versions and the level actually exercised.
- Improve documentation from real onboarding questions. Prefer independent, reproducible evidence over a new feature for every request.
- Investigate package distribution and the official MCP Registry only after verifying package-name availability, namespace ownership and current registry requirements. No package or registry listing is claimed yet.

## Measuring usefulness responsibly

Record genuine, voluntary feedback: installation outcomes, independent reproducible issue reports, accepted contributions, and maintainer-approved case studies. Repository stars, forks and release asset downloads are distinct GitHub signals, not active users. Never ask for artificial engagement or publish private reports. An absence of observed feedback is unknown adoption, not proof nobody uses the project.

Case studies must distinguish a technical finding, a proposed change, an implemented change, and observed outcomes. No guarantee or causal attribution from a simple before/after comparison. Disclose maintainer affiliation and obtain permission before naming a real website or publishing any report. Do not insert mandatory backlinks or hidden promotion into the software.
